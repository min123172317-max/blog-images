# 민솜 규칙: 글 써줘 (v3, 2026-11-25 주간 최적화로 압축)
민국 결정(2026-11-25): 규칙을 '반드시 지킬 10개'로 줄이고, 세부 형식은 `python3 tools/minsom_format.py 원고.txt --check`가 기계로 잡습니다. 같은 날 민국 지적("글이 AI가 쓴 것 같다", "소제목 5개 중 4개가 쓸데없다", "50점짜리")에 따라 문체(3-6)와 인사이트(3-8)를 새로 씁니다.

## A. 반드시 지킬 10개

3-1. 제목(후킹 공식)
  - 40자 이내, "[핵심 키워드], [독자가 궁금해할 한 문장]". 가장 강한 연관어를 맨 앞에(검색형은 검색어를 맨 앞에), 숫자 1개 이하.
  - 후킹 장치 1개 필수(본문 사실로 뒷받침). ★아래 8가지 공식은 선택입니다(2026-11-25 민국 확정: 공식만 맞춘 20편 중앙값 72회). 쓸 때는 공식 번호를 적고, 후보 2개가 같은 공식이면 안 됩니다.
    ① 대비형 "○○, A는 웃는데 B는 조용한 이유" ② 기대와 현실형 "○○, ~온다던 땅에 ~만 늘어난 이유" ③ 다들형 "○○, 다들 ~로 몰리는 이유" ④ 총력·결국형 "○○, ~까지 다 나섰는데 결국 ~될까" ⑤ 문서 발견형 "○○, 문서에 이미 ~가 적혀 있었습니다"(★1순위로 내지 않고 2순위만, 2026-11-25) ⑥ 승자 교체형 "○○, 정작 웃는 곳은 A가 아니라 B입니다" ⑦ 조용한 변화형 "○○, ~가 슬그머니(줄줄이) ~되고 있습니다" ⑧ 소문 검증형 "○○, '~'라는 말이 나오는 이유"(따옴표 안은 실제 댓글·기사 발언만)
  - ★후보 1번은 독자 동네 이름 + 구체 숫자(돈·분·년) 1개 + 동네끼리 비교를 담습니다(2026-11-25, 주간 조회수 근거: rules/data.md 8-5. 11-18 이후 공식만 맞춘 제목 20편 주간 중앙값 72회, 직전 25편 170회. 이긴 제목은 "병점역 9억 돌파, 지제역은…" 478회, "화성시 법원 예정지, 왜 동탄이 아니라 병점이…" 345회).
  - 강도어(결국·근황·다들·요즘·슬그머니·줄줄이·정작·통째로)는 한 제목에 1개. 물음표만 있는 정보형 질문은 ④·⑥·⑧과 함께일 때만.
  - 말줄임표(…)로 두 덩어리 잇기는 허용합니다(2026-11-25 민국 확정: "병점역 9억 돌파, 지제역은 아직 8억대… 1억 벌어진 이유" 478회). 한 제목에 1번만.
  - 금지: 숫자 나열, "→", 괄호 부제, 회차 번호, "총정리"·"진짜 이유"·"앞으로의 전망", 인터넷 말투·이모지. 예외: 유튜브 리뷰 시리즈는 '[이준석 리뷰N]' 머리말 허용, 머리말을 뺀 부분 40자 이내(2026-11-25).

3-2. 동탄 독자 연결
  - 독자는 동탄·수원·용인 기흥·수지에 사는 40대 이상 남성입니다. 경기남부 밖이거나 독자 관심이 낮은 지역(처인·이천·파주 등) 주제는 제목에 '동탄'(또는 수원·기흥·수지)을 넣습니다.
  - 승자·수혜 판정은 이 독자층 기준입니다(파주가 좋아지는 글이 아니라 동탄에 무엇이 달라지는 글).
  - 소제목 중 최소 1개는 첫 문장에 독자 생활 변화(몇 분·몇 회·언제)를 씁니다.
  - 동탄 권역 표기: 북부 '테크노밸리', 중앙 '동탄역 쪽', 남부 '호수공원', 동부 '동부'·'신동', 서쪽 '1동탄'.

3-3. 표기
  - 동탄역 고속열차는 'KTX'입니다(2026-09 통합). 옛 원문·주소록에 SRT로 적혀 있어도 문장은 KTX로 바꿉니다.
  - 약어는 처음에 풀어 씁니다(예: GTX(수도권 광역급행철도)). 분양 타입은 '84 타입'처럼 면적 하나로.
  - 개인정보 금지: 회사 위치는 "용인"까지만, 층수는 "저층/중층", 날짜는 월 단위, 직업·내 집 마련 이력·직접 가 본 현장은 쓰지 않습니다.

3-4. 분량·구조
  - 순서: 제목 → 서문(1~2문단, 인사말 없음) → '본문 3줄 요약' → 소제목 → '투자 유의사항' → 태그 10~15개. 목차·'정리하며'는 없습니다.
  - 분량 3,000~3,500자, 길면 5,000자까지(유의사항·태그 제외). 적중형 소제목 5개 = 정보 2 + 인사이트 3(2026-11-25 민국 확정). 검색형 3~4개(인사이트 1개 이상).
  - 소제목 하나는 700~850자, 최대 900자. 넘으면 둘로 나눕니다(2026-11-23 민국).
  - 소제목은 "1. …" 번호 + 연관어를 글자 그대로 넣은 질문형 우선. 첫 문장은 그 질문의 답(결론·수치·시점)입니다(AI 브리핑 인용용).
  - 서문 첫 두 문장은 공식 수치의 대비나 공식 발표 사실 + 핵심 키워드입니다(미리보기 문구). "커뮤니티에서 ~라는 이야기가 나온다" 금지. 서문 끝 안내 문장("공식 문서로 짚어봤습니다")은 쓰지 않습니다(2026-11-25, AI 티).
  - 문단 2~3문장, 표는 숫자 비교 때만 글당 1개('|' 줄, 열 3개·칸 8자 이내).

3-5. 본문 3줄 요약: 서문 다음 줄에 '본문 3줄 요약' 한 줄, 아래 "1. 2. 3." 세 문장. 1번에 검색어 + 수치 + 시점. 이 줄이 없으면 서식 도구가 멈춥니다.

3-6. ★문체: 항공 매뉴얼처럼(2026-11-25 민국 확정: "AI가 쓴 것 같다", "했던 말을 원론적으로 반복")
  - 한 문장에 한 사실. 60자 안팎, 80자를 넘으면 나눕니다.
  - 문단 첫 문장은 사실(숫자·날짜·기관·장소), 둘째 문장은 그 사실이 독자에게 바꾸는 것(몇 분·얼마·언제). 셋째 문장은 필요할 때만.
  - 쓰지 않는 말(AI 티): '~인 셈입니다', '~라는 점입니다', '주목할·눈여겨볼', '살펴보겠습니다·짚어봤습니다', '~를 의미합니다', '다시 말해·한마디로·무엇보다·이처럼·그렇다면', '핵심은 ~입니다', '열쇠·신호탄·판도·시계·무게' 같은 비유. 'A가 아니라 B' 문형은 글당 2곳 이내. 본문 물음표 문장 금지(질문은 소제목에만).
  - 1인칭('저는'·'제가'·'필자는')과 '~라고 봅니다'·'~라고 생각합니다' 금지. 독자에게 읽는 법을 지시하는 문장, "확인되지 않아 다루지 않습니다" 같은 한계 고지(→ 유의사항으로), 같은 말 반복 금지.
  - 누구나 아는 배경(노선 개요·사업 연혁·법정 절차 일반론·B/C 설명)은 글 전체에서 한 문단 이내.
  - 고친 예: "이는 결국 동탄 주민에게 GTX-A 이용의 문턱이 낮아진다는 점을 의미합니다." → "○○역 출근 시간 배차는 ○분입니다. ○○년 증편 계획대로면 ○분으로 줄어듭니다."(숫자는 원문에서)

3-7. 근거 문서
  - 근거는 공식 원문(계획서·보도자료 원문·고시·회의록·공단·통계의 PDF·HWP)입니다. 기사로 추론하지 않고, 공식 문서로 증명 못 하는 수치·사례는 빼거나 유의사항으로 보냅니다(악플 경험으로 가장 민감).
  - ★글감 인수인계·검색 요약·민국 메모의 수치·날짜·문구는 근거가 아닙니다. 원출처 날짜부터 의심하고, '외부 반응' 표현(카페·댓글 반응)은 본문에 옮기지 않습니다(6회 반복된 실수).
  - 원인 문장('~때문'·'~이유'·'~결과')은 원문에 그 원인이 적혀 있을 때만. 없으면 "시기가 겹칩니다"처럼 사실만 씁니다. 계산은 원문 수치로만 합니다(검색 요약 수치 금지).
  - 같은 사업에 계획 단계 B/C와 예타 B/C가 다 있으면 둘 다 단계 이름을 붙입니다.
  - 법 조문 번호 인용은 글당 1개, 나머지는 쉬운 말로 풉니다.
  - ★조사 예산(2026-11-25 민국: "사용량을 올려도 10~15곳을 조사해 복합적으로"): 적중형 웹검색 12회·공식 문서 10개 이내(검색형 4회·2개). 순서: ⓪ data/blocked_sites.md를 사이트·언론사 이름으로 grep ① `topic_scan.py --kw` ② addressbook.tsv grep ③ 같은 주제 기존 글의 근거 문서 ④ 부족한 것만 검색(allowed_domains에 기관 도메인). 언론사 주소는 1회 실패하면 바로 공식 원문으로. 정밀(extended) 검색은 일반·기관 검색이 모두 실패한 뒤에만. 문서는 필요한 쪽만 읽습니다.

3-8. ★인사이트(정보 2 + 인사이트 3, 2026-11-25 민국 확정)
  - 정보 소제목 2개: 독자가 검색하는 답(언제·어디·얼마·노선도·정거장)만 씁니다. 일반론 없이 첫 문장에 답. 정보끼리 겹치면 1개로 합칩니다.
  - 인사이트 소제목 3개, 각각 세 가지를 다 갖춥니다: ⓐ 기사에 없는 '새로 알게 되는 한 문장' ⓑ 서로 다른 공식 문서 2개 이상을 엮은 근거 ⓒ 직접 계산한 숫자 1개(계산 과정은 문단으로 풂).
  - 인사이트로 치지 않는 것(민국 50점 판정): "A는 x, B는 y"로 끝나는 단순 비교 / 누구나 아는 사실·원론(B/C·법정 절차·서명운동·사업비 나열) / "지켜봐야 한다" 결론 / 다른 소제목의 결론·핵심 숫자 반복(겹치면 합치고 새 인사이트로, 민국 4회 지적).
  - 인사이트를 만드는 틀(하나 고름): ① 문서끼리 숫자가 어긋나는 곳 ② 두 사업 일정이 겹치거나 순서가 바뀌는 곳 ③ 용량 병목 계산(배차·좌석·차로·주차) ④ 수요 이동(통계 교차표의 권역 차이, 직장인형은 필수) ⑤ 선례 대입(같은 유형 사업의 실제 소요 기간을 이 사업에 대입해 시점 하나 계산) ⑥ 돈의 주인(누가 내고 누가 얻나: 분담 비율·연차 예산). 비교는 "왜 차이가 났는지 + 독자에게 몇 분·얼마·언제 달라지는지"까지 가야 인사이트입니다.
  - 찾는 곳: 돈(총사업비 변동·분담 비율) / 절차(다음 관문과 통상 기간) / 사양(배차·편성·정거장·차로·용적률) / 수요(예타·영향평가 속 이용객·교통량) / 쟁점(회의록·공청회 반대 의견과 답변) / 조문(결정권 주체·간주 조항·기준 시점·예외 단서, `python3 tools/law_fetch.py "법령" 조번호`).
  - 계산형 글은 가정 숫자 대신 실제 단지 1곳의 공식 숫자(관리처분 고시 비례율·공시가격)로 예시를 듭니다. 시나리오 확률(%)은 쓰지 않고, 근거로 주장할 수 있는 시점 하나 + 밀릴 수 있는 이유 + 비슷한 사업 사례를 씁니다. 이미 여러 번 쓴 비교 사례는 반복하지 않습니다.
  - 반도체 글 흐름: 착공·투자 → 고용 인원 → 필요한 주택 수 → 통근권. 집값 이유는 한 요인으로 단정하지 않고 지역별 선택 이유(교통·학군·인프라·일자리)를 비교합니다.

3-9. 결론: 마지막 소제목 끝은 1인칭 없는 단정형 결론 + 이유 한 문장(예: "서부선의 첫 확정 신호는 착공식이 아니라 재공고 사업비 발표입니다. 사업비를 42% 올리고도 민자가 성사되지 않으면 남는 길은 재정 전환뿐이기 때문입니다."). 의문문·"지켜봐야" 금지. 빈 줄 뒤 '함께 읽으면 좋은 글입니다.' 한 줄.

3-10. 투자 유의사항: 4~5문장. ① 기준 시점(월 단위)·참고용(매수·매도 권유 아님) ② 계산의 핵심 가정 ③ 예시·보도 내용이 실제와 다를 수 있음 ④ 계산에서 뺀 항목 ⑤ 규제·발표로 바뀔 수 있음. 비슷한 항목은 한 문장에 묶습니다. 미공개·미확인 사항은 여기에만 씁니다.

## B. 쓰는 순서
3-11. 명령 "글 써줘: [주제]"(옵션 + 최종 / + 강조: / + 제외: / + 검색형 / + 내 지식:). "+ 내 지식"은 그 내용을 중심 각도로 삼고 공식 문서로 뒷받침하되 개인 경험은 드러내지 않습니다. 강조점이 없어도 먼저 각도를 잡아 씁니다. 요청 주제에서 다른 사업 중심으로 바꾸지 않습니다.
  ① 유형: 적중형(직장인·사건) / 검색형(노선도·위치·개통 시기·블록 이름).
  ② 기존 글 대조: `topic_scan.py --check 키워드`. 같은 내용을 제목만 바꿔 쓰지 않고, 겹칠 것 같으면 먼저 묻습니다. 글마다 독립적으로 읽히게 씁니다("9월에 쓴 글에서는" 금지).
  ③ 연관어: `topic_scan.py --kw "핵심" "보조"`(웹검색 0회, 추측 키워드 금지). 가장 강한 연관어를 제목 앞에, 3줄 요약 1번에 1개, 소제목 2개 이상에 글자 그대로, 태그는 연관어 먼저. 연관어가 묻는 질문(노선도·착공·개통)은 본문에서 답합니다.
  ④ 조사(3-7 예산) → ⑤ 설계표: 인사이트 3개를 한 줄씩 '새 문장 / 문서 2개 / 계산'으로 정합니다. 하나라도 못 채우면 각도를 바꿉니다.
  ⑥ 초고 → ⑦ 원고를 파일로 저장해 `python3 tools/minsom_format.py 원고.txt --check`를 돌리고 '확인 필요'가 없을 때까지 고칩니다 → ⑧ 납품.

## C. 자동 점검(--check가 잡는 것: 사람이 외우지 않아도 됨)
3-12. 제목 40자·숫자 나열·'→'·독자 동네 이름 없음 / 금지 표기(SRT·결절점·총정리·진짜 이유·앞으로의 전망·여러분은 어떻게·정리하며) / 1인칭 / AI 티 표현 2곳 이상 / 'A가 아니라 B' 3곳 이상 / 80자 넘는 문장 / 본문 물음표 / 분량 3,000~5,000자 / 소제목 6개 이상 / 소제목 900자 초과 / 가장 긴 소제목이 가장 짧은 것의 1.5배 초과 / 마지막 문장 의문문 / 법 조문 번호 2종 이상 / 유의사항 6문장 이상 / 표 2개 이상·열 4개 이상·칸 8자 초과 / 4문장 이상 문단 / 태그 없음. 걸리면 원고를 고칩니다(민국에게 넘기지 않음).

## D. 납품·발행
3-13. 초고 납품(코드 블록 없이 순수 텍스트): 설계표 3줄 → 제목 후보 2개(순위·후킹%·키워드 강도·공식 번호(쓴 경우)·이유) → 원고 → 태그 10~15개 → '연관 키워드: …' 한 줄 → 결론을 좌우하는데 확신 못 한 항목(직접 1회 더 찾은 뒤에만) → 썸네일 추천 한 줄(노선도·위치도 중 무엇, 어느 공식 문서). 근거 문서로 확인한 숫자만 넣고, 출처 목록·근거 흐름·형광펜·링크·'(추론)' 표기는 없습니다.
3-14. 수정·최종·발행
  - 수정 요청은 해당 부분만 고치되 원고 전체를 다시 줍니다. 독자 댓글로 오류 지적이 오면 즉시 고칩니다.
  - 발행 명령: "최종 원고로 발행해줘"·"최종 원고로 써줘"·"최종으로 써줘"·음성 오인식 "제 종목으로 발행해줘"는 모두 같습니다. 셀프 검토 없이 최신 원고로 확정하고, 근거 문서(주소·쪽·그림 쪽·숫자의 출처 고시·조문)를 addressbook.tsv에 조용히 추가하고, 피드백을 data/feedback/YYMMDD-폴더-글.md로 남겨 push → main까지 합친 뒤, rules/handoff.md 7-B대로 이미지 방을 만듭니다. 원고 코드 블록은 민국이 "원고 보여줘"라고 할 때만 줍니다. 처음부터 "+ 최종"이면 초안 없이 같은 흐름입니다.
  - 피드백 파일 항목: ① 사용량 ② 정확도(틀린 문장 인용·원인) ③ 인사이트 ④ 민국 지적(data/feedback/README.md 양식). 규칙은 수요일 주간 최적화에서 고치고, 도구 오류·사실 오류 원인·같은 날 같은 실수 2회만 바로 고칩니다.
  - "자동서식 적용해줘"는 이미지 없이 서식만 필요할 때의 단독 명령입니다(rules/format.md).

## E. 운영·특수 유형
3-15. 한 채팅에 글 1편, 하루 3편 상한(적중률 우선: 10월 57편 중 15편이 조회수 대부분). 수정이 1곳이면 "N번 소제목만"처럼 지정합니다.
  - 쓰지 않는 주제는 rules/topic.md 2-8과 같습니다. 민국이 직접 지정하면 쓰되 "조회수가 낮았던 유형" 한 줄만 알립니다.
  - 천지개벽 시리즈("천지개벽 시리즈 ○○역으로 해줘"): 개발사업·교통망 변화 → 역 기능 변화 → 유동인구·생활권·상업 → 주거·위상 → 부동산 영향과 한계 순. 사업 단계와 목표 일정을 구분하고 공정률로 개통 시점을 계산합니다. 제목 "[○○역], [궁금증 한 문장]", 큰 발표가 있으면 '○○역 그 후' 업데이트편. 이미 쓴 역: 화서, 영통, 평촌, 산성·구성남, 병점, 매교, 구성, 광교중앙, 인덕원, 금정, 야탑, 기흥, 수지구청.
  - 이슈글은 시의성 도입 → 실수요자 영향 → 결론, 내집마련 시리즈는 경험 서사 → 개념 → 마지막 인사이트(다음 편 예고 없음). 기사 구조를 그대로 따르지 않습니다. 제목에 독자가 아는 기업 약칭(예: AMAT)을 넣습니다.
