# 민솜 규칙: 새 채팅방 자동 넘기기 (2026-11-19 민국 확정)
민국이 코드 블록을 복사해 새 채팅방에 붙이던 일을 이 방이 직접 합니다. 새 채팅방은 `mcp__claude-code-remote__create_session`으로 만듭니다(2026-11-19 시험: 새 방이 저장소를 읽고, 그 방도 다음 방을 만들 수 있음 확인).

## 7. 넘기기 규칙
7-1. 언제: ① 글감 방(배달 방 '민솜 글감 배달 (MM/DD)' 또는 "글감 찾아줘"·"서울 글감 찾아줘"를 한 방)에서 "N번 글 써줘" / "N번 서울 글 써줘" ② 글 방에서 "최종 원고로 발행해줘"·"최종 원고로 써줘"·"최종으로 써줘"·음성 오인식 "제 종목으로 발행해줘"(수정 지시가 붙어도 같음). 이 두 경우에는 이 방에서 글·이미지를 만들지 않고 새 채팅방으로 넘깁니다. 확인 질문 없이 바로 넘깁니다.
7-2. 도구 불러오기: `mcp__claude-code-remote__create_session`이 목록에 없으면 ToolSearch로 "select:mcp__claude-code-remote__create_session"을 부릅니다. 방금 연 방은 원격 도구 연결이 늦어 처음엔 안 보일 수 있으니 한 번 더 부릅니다. 그래도 없거나 만들기가 실패하면 옛 방식(새 채팅방에 붙일 코드 블록)으로 주고 "자동 넘기기 실패: (오류 한 줄)"을 적습니다.
7-3. 새 방 만드는 법(공통): source_url `https://github.com/min123172317-max/blog-images`, title·prompt만 넣습니다. model·effort·permission_mode·environment_id는 넣지 않습니다(이 방 설정을 물려받음). 만든 뒤 그 방을 확인하거나 기다리지 않습니다(get_session·list_events 금지, 사용량 절약). 새 방은 민국 앱의 채팅 목록에 바로 뜹니다.

## 7-A. 글감 → 글 쓰기 방
7-4. 번호: 배달 목록의 번호(rules/topic.md 2-9, 모든 글감에 1번부터 이어지는 번호)를 따릅니다. 번호 대신 주제 이름으로 말해도 같은 글감을 찾아 넘깁니다. 어느 글감인지 둘 이상으로 읽힐 때만 한 줄로 묻습니다.
7-5. 여러 개를 한 번에: "1번, 3번 글 써줘, 7번 서울 글 써줘"면 번호마다 방 1개씩 만듭니다(한 방에 글 1편, write.md 3-15). 서울 칸 글감이면 "서울"을 안 붙여도 서울 글로 넘깁니다. 하루 3편 상한(write.md 3-15)을 넘으면 그대로 만들고 "오늘 N편째(상한 3편)" 한 줄만 붙입니다.
7-6. 방 제목: 민솜 "글: [주제] (MM/DD)", 서울 "서울 글: [주제] (MM/DD)".
7-7. 새 방에 보내는 prompt(이 틀 그대로, 칸이 없으면 줄을 뺌):
```
글 써줘: [주제]          ← 서울이면 "서울 글 써줘: [주제]"
[민국이 붙인 옵션·지시 그대로: + 강조/+ 제외/+ 검색형/+ 내 지식/+ 최종, 또는 "이런 부분 더 넣어서" 같은 말 그대로]

[글감 배달 인수인계 (MM/DD N번)]
제목안: …(후킹 공식 번호, 쓴 경우)
각도: …
출처 구분: [공식]/[특집]/[철도-소식]/[철도-시각]/[철도-연결]/[넓히기]/[연재] (2026-11-25 관찰 태그, topic.md 2-6)
부동산 엮기: …(철도 글감만, topic.md 2-23-2)
근거 문서: 기관·보도자료(또는 특집 자료) 제목·발표일·원문 주소([공식]·[특집] 글감만, topic.md 2-21-5·2-22-7)
이유: …(외부 반응 숫자, [반응] 글감만)
연관 검색어: …(2-9-1: 실제로 뜬 것만, 없으면 '(연관어 없음)')
썸네일 종류: …
기억 근거: …
법안: 의안번호·원문 주소(있을 때만)
※ 위 제목안·각도는 참고입니다. 규칙 파일(CLAUDE.md 표의 명령별 파일)을 먼저 읽고 그 규칙대로 씁니다.
※ 위 수치·외부 반응 문구는 근거가 아니므로 공식 원문으로 확인한 것만 본문에 씁니다.
```
7-8. 글감 방 답변: 방마다 한 줄 "N번 → 새 채팅방 '방 제목' 만들었습니다"만 씁니다. 코드 블록·원고는 쓰지 않습니다.

## 7-B. 최종 원고 → 이미지 찾기 방
7-9. 순서(반드시 이 순서): ① 수정 지시가 있으면 원고에 반영 ② write.md 3-14 addressbook.tsv 추가 + 피드백 파일 → 커밋 → 작업 브랜치 push → main까지 합침(새 방이 main을 읽으므로 먼저 끝내야 함) ③ 새 방 만들기.
7-10. 방 제목: 민솜 "이미지: [발행 제목 앞 20자] (MM/DD)", 서울 "서울 이미지: [발행 제목 앞 20자] (MM/DD)".
7-11. 새 방에 보내는 prompt:
```
이미지 찾아줘          ← 서울 글이면 "서울 이미지 찾아줘"
[최종 원고: 제목·본문·태그 전체, 3-14 최종 원고 그대로, 한 글자도 줄이지 않음]
```
7-12. 글 방 답변: "최종 원고 확정 → 새 채팅방 '방 제목' 만들었습니다 / 피드백 기록함" 두 줄 + 최종 원고 전체 코드 블록(제목·본문·유의사항·태그, 한 글자도 줄이지 않음)을 줍니다(2026-11-25 민국 "앞으로 무조건 원고는 보여줘"). 민국이 그 회차만 "안 보여줘도 돼"라고 하면 생략합니다.
7-13. 이미지 방은 rules/image.md 4-8대로 납품합니다(서식 페이지가 최종본). 이미지 방에서 다시 넘기는 일은 없습니다.

## 7-C. 서울교통 글 → 민솜판 (2026-11-25 민국 확정)
7-14. 명령: 서울 아티팩트(서식 페이지)가 있는 방에서 "민솜 버전으로 만들어줘", 또는 아무 새 방에 서울 아티팩트 링크 + "민솜 버전으로 만들어줘". 원본 방은 글·이미지를 만들지 않고 새 방만 만듭니다(한 방 한 글, seoul.md 6-1). 확인 질문 없이 바로 넘깁니다.
  · 대상: 경기 남부(동탄·화성·수원·용인·성남·평택)와 이어지는 서울교통 글만. 정비사업 글이거나 경기 남부 연결이 없으면 새 방을 만들지 않고 이유 한 줄로 끝냅니다.
7-15. 방 제목: "민솜판: [주제] (MM/DD)". 원본 방 답변은 한 줄("민솜판 → 새 채팅방 '방 제목' 만들었습니다")입니다.
7-16. 새 방 prompt(이 틀 그대로):
```
민솜 버전으로 만들어줘
원본 아티팩트: [서울 서식 페이지 링크]
원본 발행 제목: [서울 글 제목]
2순위 이미지 후보: [원본 방 납품의 보조·예비 후보 목록, 없으면 '(없음)']
※ rules/handoff.md 7-C를 먼저 읽고 그대로 합니다.
```
7-17. 새 방 순서(원고 확인 없이 끝까지 한 번에, 2026-11-25 민국):
  ① rules/write.md + rules/image.md + rules/format.md를 읽습니다.
  ② Artifact read로 원본을 엽니다. 원본은 자료 창고(공식 수치·출처)로만 쓰고 문장은 옮기지 않습니다.
  ③ 민솜 원고(write.md 규칙 그대로): 제목·서문 새로 씀(경기 남부 지역명 1개 필수) / 소제목 3개 이상은 새 질문(동탄·수원·용인 출발 소요 시간, 환승 동선, 경기 구간 일정 등) / 나머지 소제목도 문단을 새로 씀 / 새 계산 1개 이상 / 웹검색 2회 이내.
  ④ 겹침 검사: 원본 본문을 txt로 저장한 뒤 `python3 tools/overlap_check.py 원본.txt 새글.txt`. 전체 30% 이하 + 제목·첫 문단 30% 이하가 될 때까지 표시된 문단을 다시 씁니다.
  ⑤ 이미지(image.md 4번): 핵심 노선도는 다시 잘라 재사용 / 썸네일은 반드시 원본과 다른 이미지 / 보조 자료는 2순위 후보로 교체. 후보가 모자랄 때만 웹검색 1회.
  ⑥ 서식(format.md) 적용 → 새 아티팩트 발행(원본 아티팩트는 고치지 않음). 두 글은 서로 링크·언급하지 않습니다.
  ⑦ write.md 3-14 addressbook.tsv 추가 + 피드백 파일(data/feedback/YYMMDD-글폴더-민솜판.md, 겹침 % 기록) → 커밋 → main까지 합침.
  ⑧ 답변: 최종 원고 전체 코드 블록 + 서식 페이지 링크 + 겹침 % + 발행 권장일(서울 글 발행 5~7일 뒤, 같은 날 금지) + 휴대폰 알림. 수정 요청은 같은 아티팩트를 부분 수정합니다.
